# MDedit v0.3.10

## Persistent app-wide compatibility saving

Open **Editor → Allow compatibility saving** on desktop to remember your choice for all eligible files across restarts.

- Off by default, with a permission/ownership warning before enabling.
- When enabled, eligible WSL/non-ACL saves no longer require repeated per-file confirmation.
- Turning it off clears session approvals and restores per-file prompts.
- A failed preference write does not silently enable the setting. Disabling takes effect immediately even if persistence fails, with an explicit warning that it may return after restart.
- The setting is stored in the app's local profile, not inside the portable executable, and is not offered in the plain-browser editor.

**Permission tradeoff:** compatibility saving uses folder-default temporary permissions. Replacement may change permissions, ownership, or access ACLs and make the temporary or saved file readable by more people. Enable it only if you accept this tradeoff.

Native saving safeguards are unchanged: ACL-capable filesystems keep permission-preserving saves, compatibility saves use flushed temporaries and rename replacement, and disk-conflict checks remain active. No direct-overwrite or delete-then-rename fallback is introduced.

## Regression coverage

Added controller and browser tests for app-wide permission, persistence across reloads, multiple-file saving, default cancellation, disabling and stale approvals, storage failures, and browser-only behavior. The release pipeline runs desktop builds/native tests on Windows, Linux, and macOS plus browser and performance gates.
