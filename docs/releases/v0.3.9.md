# MDedit v0.3.9

## Opt-in WSL compatibility saving

Existing files on WSL and other filesystems without Windows ACL support can now be saved using explicit compatibility mode instead of v0.3.8's blanket refusal.

When you save, choose **Use Compatibility Saving** in the warning dialog. **Cancel** is focused by default and leaves the file unchanged. Approval applies only to that resolved file path for the current application session; restarting MDedit clears it. Save As over another existing path requires separate approval.

**Important permission tradeoff:** compatibility saving creates a temporary file with folder-default permissions and renames it over the original. Permissions, ownership, or access ACLs may change, and the temporary or saved file may be readable by more people. A disposable Windows-to-WSL probe demonstrated mode `0600` changing to `0644`. Use compatibility mode only if you accept that tradeoff.

## Safeguards

- Write and flush a same-directory temporary before rename replacement; no direct-overwrite or delete-then-rename fallback.
- Repeat content-conflict checks and bind approval to the exact, case-preserving resolved path.
- Keep existing Windows ACL-preserving saves unchanged on ACL-capable filesystems.
- Preserve dirty edits on cancellation, conflict, or error; do not retry publication through another strategy after failure.
- Retain recoverable temporary files after uncertain failures and report their paths.

## Coverage

Added native policy/publication tests, controller tests, and a browser test for confirmation, default cancellation, and session-scoped consent. The chosen Windows rename operation was independently verified on disposable mapped-drive and UNC WSL fixtures.

The release pipeline runs Windows, Linux, macOS, browser, and performance gates. The separate compiled-app WSL-provider workflow requires a configured self-hosted WSL runner; the primitive probe is not a claim of full WSL application integration or crash-durability validation.
