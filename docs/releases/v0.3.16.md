# MDedit v0.3.16

## HTML and web links

- Desktop preview links to HTTP(S) websites open through the system browser launcher instead of relying on WebView popup behavior. Protocol-relative web URLs use HTTPS.
- Relative and absolute `.html`/`.htm` references, including local `file:///` URLs, open externally. Relative paths resolve beside the saved Markdown document; query strings, fragments and escaped filenames are preserved.
- Left- and middle-clicks are supported. Cached previews rebind links to their current document, and stale or detached anchors cannot launch a target.
- HTML links no longer also trigger attachment downloads. Other attachments retain their existing behavior; local Markdown links still open or activate MDedit tabs.
- Browser-only web links retain standard browser new-tab behavior.

## Safety and limitations

- Native validation permits only HTTP(S) URLs and canonical existing local HTML files. Missing files, directories, remote file hosts, unsupported schemes and HTML symlinks resolving to another file type are rejected.
- Unsaved documents must be saved before relative HTML links can resolve. Opener failures are reported without navigating away from MDedit.
- The system's browser settings and file associations determine the receiving application and whether it opens a new tab or window. Desktop downloads remain unsigned.

## Verification

The feature commit passed main-branch CI on Windows, macOS and Linux, including native-core tests and all 142 functional/security browser tests. The Linux release-WebView smoke test verifies native URL validation and launcher dispatch using a recording substitute for `xdg-open`; it does not open an actual user's browser. The release workflow also requires the unchanged performance gates before publication.
